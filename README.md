# school-helper

Telegram-бот и Mini App для родительского комитета класса: сборы денег, голосования,
расписание, объявления и хроника событий.

Принцип: **Telegram — поговорить, school-helper — зафиксировать.**
Обычный родитель приложение не открывает — всё, что от него нужно, делается кнопкой
под сообщением бота.

Полная спецификация: [docs/SPEC.md](docs/SPEC.md).

---

## Что уже работает

**Бот — для всех родителей.** Команда у него одна — `/start`, всё остальное
приходит само, кнопками под сообщениями:

- подключение: `/setup` в группе → ссылка-приглашение → анкета в личке;
- «Я оплатил» → скрин чека → подтверждение казначея → строка в журнале;
- объявление о сборе в группе с полосой прогресса и личное сообщение каждому;
- быстрые кнопки «Подтвердить / Не вижу» у казначея в личке;
- бот работает только в группе своего класса: из любой другой, куда его
  добавил не председатель, он сразу выходит;
- повторная заявка невозможна, если взнос уже принят, родитель освобождён
  или прошлая заявка ещё ждёт подтверждения;
- очередь уведомлений с ретраями и учётом заблокировавших бота.

**Mini App** (кнопка «Класс» в боте) — касса и свои взносы для родителей,
рабочее место для комитета:

- главная: что ждёт действия именно от вас, касса, идущие сборы;
- сборы: создание формой, поимённый разрез, «сдал наличными», освобождение, закрытие;
- платежи: очередь с фото чеков, подтверждение и отклонение;
- люди: приглашение, роли переключателями, родители без Telegram, исключение;
- класс: название, реквизиты карты, статус привязки группы.

Что специально сделано именно так:

- в группу уходят только сумма и полоса прогресса — **без имён и без «17 из 24»**;
- поимённый разрез сбора доступен только казначею, председателю и ревизору;
- **учителю денежный раздел не показывается вообще**;
- деньги попадают в журнал только при подтверждении казначея;
- журнал неизменяем: правка = сторно.

## Запуск

```bash
python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"

cp .env.example .env    # заполнить BOT_TOKEN, BOT_USERNAME, APP_SECRET
.venv/Scripts/python -m schoolhelper.runner
```

`APP_SECRET` генерируется так:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

### Первый запуск

1. Создать бота у [@BotFather](https://t.me/BotFather) и выключить ему Group Privacy
   (Bot Settings → Group Privacy). Команды со слэшем бот видит и так — это нужно
   для объявлений учителя, где председатель отвечает реплаем на её сообщение.
2. Прописать свой Telegram id в `BOOTSTRAP_CHAIR_TG_ID` — тогда достаточно написать
   боту `/start` в личке: выдадутся роли председателя и админа.
3. Добавить бота в группу класса администратором (нужно право закреплять сообщения).
4. В группе: `/setup` (работает только у председателя) → появится кнопка-приглашение.
   После этого у @BotFather можно выключить **Allow Groups** — тогда бота вообще
   нельзя будет добавить в другие группы. В группе класса он останется.
5. В личке с ботом — кнопка **«Класс»**: там роли, реквизиты карты, сборы и платежи.
   Кнопка появляется, когда настроен домен (docs/DEPLOY.md, §6).

### Прод

Push в `main` → GitHub Actions гоняет тесты → собирает образ и кладёт в GHCR →
сервер забирает готовый образ и проверяет `/health`, с автоматическим откатом
при неудаче. Образ собирается в Actions, а не на VPS: там 1.9 ГБ памяти на все
проекты. Настройка сервера и секретов — [docs/DEPLOY.md](docs/DEPLOY.md).

Режим выбирается сам: без `PUBLIC_URL` бот работает опросом (домен не нужен),
с доменом — переключается на вебхук. HTTP-сервер поднят в обоих случаях,
чтобы у деплоя была проверка живости.

### Mini App локально

Интерфейс разрабатывается в обычном браузере, без Telegram:

```bash
# терминал 1 — бэкенд; в .env: DEV_AUTH_TG_ID=<ваш tg id>, BOT_POLLING=0
.venv/Scripts/uvicorn schoolhelper.app:app --port 8080

# терминал 2 — фронтенд с горячей перезагрузкой
cd webapp && npm install && npm run dev      # http://localhost:5173
```

`DEV_AUTH_TG_ID` пускает под указанным пользователем только с localhost и
отключается сам внутри Docker. `BOT_POLLING=0` нужен, если этот же бот уже
работает на сервере: Telegram не даёт двум процессам опрашивать один токен.

## Тесты

```bash
.venv/Scripts/python -m pytest -q
.venv/Scripts/python -m ruff check src tests
cd webapp && npm run build                    # типы + сборка интерфейса
```

Тесты закрывают то, что дороже всего сломать: денежные инварианты, сторно,
проверку `initData`, разграничение доступа к поимённым спискам и чекам,
правила выдачи ролей (класс не остаётся без председателя).

## Известные ограничения

- FSM-состояния живут в памяти: при рестарте незаконченный диалог
  (например, «пришлите чек») теряется. Для этапа 1 это допустимо.
- Файлы хранятся в Telegram по `file_id` — при смене токена бота ссылки на чеки
  перестанут открываться. Раз в год нужна выгрузка архива.
- Telegram-платежей нет и не планируется: провайдеры требуют мерчант-аккаунт
  юрлица. Схема «реквизиты + скрин + подтверждение» — постоянная.
